# Website Factory, Structure Overview

## What the Factory does

The factory runs a deterministic 13-stage per-client pipeline. It clones the active niche template (generated by Module 2D), overlays per-client brand DNA, copy, and assets, builds a production Vite + React site, validates it against niche-specific QA checklists, deploys to Vercel, and generates a client proposal.

There is no shared baseline template. Every niche has its own template generated from captured research. If no per-niche template exists, the pipeline halts and points back to `/build-niche-template`.

**Active niche template:** `website-factory/templates/landscaping/`

---

## Pipeline stages

| Stage | Name | What happens | Output path |
|---|---|---|---|
| 1 | Intake | Validate 4 fields (businessName, websiteUrl, phone, email), scaffold client folder | `clients/[Client]/Pipeline Data/intake/` |
| 2 | Research | GBP + social + competitor scrape via Apify | `clients/[Client]/Pipeline Data/research/` |
| 3 | SEO audit | Local keyword strategy, GBP density, schema plan | `clients/[Client]/Pipeline Data/seo/` |
| 4 | Asset harvest | Logo, photos, project images, team photos from site + GBP + social | `clients/[Client]/[Client] Assets/` |
| 5 | Strategy | Sitemap, service page plan, positioning | `clients/[Client]/Pipeline Data/strategy/` |
| 6 | Copywriting | Full site copy: every H1, body, FAQ, owner story, CTA | `clients/[Client]/Pipeline Data/copy/` |
| 7 | Brand DNA | Extract palette, typography, motif from logo + copy; populate canonical shape | `clients/[Client]/Pipeline Data/brand/` |
| 7.5 | Brand resonance | Optional: visual analysis of old site for resonance signals | `clients/[Client]/Pipeline Data/brand-resonance/` |
| 9 | Hero image | Generate hero via Gemini (Nano Banana 2) per niche composition rules | `clients/[Client]/Pipeline Data/hero-image/` |
| 10.1 | Build | Clone niche template, overlay brand-dna.json, run `npm run build` | `clients/[Client]/[Client] Website/dist/` |
| 10.2 | Personalise | SEO injection, schema markup, sitemap.xml | Same |
| 10.3 | Uplift | Niche-specific polish per playbook | Same |
| 10.4a | Design QA | SSIM vs niche template reference render | QA report |
| 10.4b | SOP QA | Universal + per-niche SOP compliance scoring | QA report |
| 10.4c | Build fidelity | DOM diff vs niche template reference build | QA report |
| 10.4d | Perf | Lighthouse LCP gate (< 3s desktop AND mobile) | QA report |
| 11 | Deploy | Vercel production deploy | `clients/[Client]/Pipeline Data/deploy/` |
| 12 | Delivery | Delivery report | `clients/[Client]/Pipeline Data/delivery/` |
| 13 | Proposal | HTML proposal generation + live URL | `clients/[Client]/[Client] Proposal/` |

**Approval gate:** Stage 7 halts if brand-dna extraction confidence is below 0.70. Student runs `/approve-brand-dna` to continue.

**Pipeline entry point:** Run `/build-all` from inside `website-factory/` to start the full pipeline for a client.

## Inputs the factory needs (per client)

Minimum 4 fields at intake:
- `businessName` - the landscaping company name
- `websiteUrl` - their current website (even if bad)
- `phone` - owner's phone
- `email` - owner's email

The intake agent scaffolds the full client folder from these 4 fields. Downstream stages populate the rest automatically.

Client folder structure:
```
clients/[Client Name]/
  Pipeline Data/
    intake/           intake-form.json
    research/         research.json
    seo/              audit-data.json
    strategy/         strategy.json
    copy/             copy-deck.md
    brand/            brand-dna.json
    brand-resonance/  (optional)
    hero-image/       hero-final.png
    deploy/           deploy.json
    delivery/         delivery-report.md
    lessons/          notes.md (client-specific corrections)
  [Client Name] Assets/
    logo/             primary logo file
    photos/           project photos
    team/             owner and crew photos
    trust-badges/     certifications, awards
  [Client Name] Website/
    dist/             built site files
  [Client Name] Proposal/
    proposal.html     client-facing proposal
```

## Canonical brand-dna shape

Every component reads from one data contract: `references/brand-dna.shape.js`. This 32-key shape covers:

- `meta` - title, description
- `company` - name, tagline, url, licenseNumber, serviceRegion
- `contact` - phone, email, maps links
- `address` - full address + lat/lng
- `palette` - primary, accent, surface, text (4 required + optional stops)
- `typography` - heading font, body font, weights, scale
- `hero` - headline, subheadline, primary/secondary CTA
- `services` - array of service objects
- `gallery` - project array with before/after, type, investment range
- `team` - owner + crew member array
- `reviews` - curated review array
- `trustSignals` - certifications, badges, guarantees
- `faq` - Q+A array
- `serviceArea` - cities and neighborhoods served
- `copy` - section-level copy overrides
- `pages` - per-route SEO titles and descriptions

Stage 7 fills this shape from the client's assets and brand research. Stage 10.1 injects it into the niche template's `src/config/brand-dna.js` before building.

## Universal defaults (apply to every niche)

- Theme mode logic (light vs dark) derived from logo brightness
- Build stack: Vite + React 18 + Tailwind CSS
- SEO injection: LocalBusiness schema, service schema, sitemap.xml
- Lighthouse performance gate: LCP < 3s on desktop and mobile
- Vercel deploy with custom domain support
- AI-vocab blocklist enforced on all copy (no "seamless", "leverage", "robust", etc.)
- No em-dashes anywhere in output
- Typographic standards: no widows, no orphaned CTAs

## Key commands (run from inside `website-factory/`)

| Command | What it does |
|---|---|
| `/build-all` | Full pipeline end-to-end for the active client |
| `/stage7` | Brand DNA extraction only |
| `/approve-brand-dna` | Approve brand DNA after low-confidence extraction |
| `/stage9` | Hero image generation |
| `/stage-10-1-build` | Build only (skips stages 1-9) |
| `/lesson "<correction>"` | Log a correction into the lessons ledger |
| `/lessons` | Print all accumulated lessons |

---

## Self-improvement: lessons ledger

Every agent reads `.claude/lessons/by-agent/<agent-name>.md` before running. When the student corrects an output, they run `/lesson "<correction>"`. Lessons take precedence over the agent spec. This means the factory gets better with each client run without needing to rewrite the spec.

---

## Handoff from the parent stack

The Module 5 brief (`research/output/website-factory-brief.md`) is the document that tells the factory what kind of clients it will be serving and how to tune any factory-wide settings. `/tailor-factory` reads the brief and applies niche-level adjustments (proposal template, agency branding, default service set).
